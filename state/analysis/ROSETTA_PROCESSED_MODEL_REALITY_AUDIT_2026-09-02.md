## Bottom line
The active Rosetta `rosetta_unified` products are **not runnable model checkpoints, not trainable weight sets, and not lossless stripped brains**. They are compact **relational/forensic descriptor corpora** generated by inspecting source model files.

The source model checkpoints remain separate.

## What the converter actually does
Active converter:
`E:/models/99-labs/PCMMAD_TQ2_GEOMETRIC_LAB/code/rosetta/quant_aware_convert_weights_to_relational_corpus_working.py`

For safetensors it:
- opens the real tensor files;
- records tensor names, storage/logical shapes, dtypes, layer indices, heuristic role/family guesses;
- records approximate storage/logical parameter counts;
- for dense tensors, samples at most 16,384 tensor elements and computes mean/std/min/max/L2/near-zero fraction;
- for one supported nibble-packed U32 quantization form, samples approximate dequantized values plus scale/bias statistics;
- writes `tensors.jsonl`, `families.json`, `stats.json`, `manifest.json`;
- the unified layer additionally writes `descriptor_bundle.json` and `normalized_manifest.json`.

It does **not** serialize full tensor values into Rosetta output.

The typed descriptor layer explicitly says the output is a descriptor surface and warns against naive dense flattening. Rosetta's own doctrine says `Rosetta is leverage, not proof`.

## Information-loss proof from actual sizes
Examples from live E-drive Rosetta:

- Qwen3.5-9B source (`qwen35_4shard`): ~17.980 GiB; Rosetta output: ~2.185 MiB.

- DeepSeek-R1-Distill-Qwen-32B source: ~61.028 GiB; Rosetta output: ~2.026 MiB.
- Phi-4 source: ~27.305 GiB; Rosetta output: ~0.630 MiB.

These compression ratios are impossible for a lossless weight representation. The Rosetta outputs cannot reconstruct the source checkpoints.

## Provenance-hash caveat
The current Rosetta `ProvenanceDescriptor.source_hash` is computed as SHA-1 of the text string `source_file_path::tensor_name`, **not a content hash of the tensor bytes or source file**. `name_hash` similarly hashes the tensor name. Therefore Rosetta sidecars are not cryptographic weight identity proofs by themselves.

## Correct interpretation of Rosetta's purpose
Rosetta was built as a normalized comparison/intake surface for TQ2:
- align tensor names/roles/families/layers across formats;
- expose storage-vs-logical shape and quantization structure;
- generate compact statistics for comparison;
- let recipe/evaluator tooling reason about candidate model structures without loading every full model each time.

The Monster bridge explicitly treats auxiliary Rosetta outputs as sidecars and says native replay/specimen truth outranks Rosetta-derived claims.

## Superseded language
The phrase **"Rosetta-stripped model weights"** is misleading for the active unified output and should be retired unless it refers to a different artifact that actually contains transformed weights.

Preferred language:
> **Rosetta normalized tensor-descriptor / relational corpus derived from model weights.**

## Operational consequence
- Train/infer using the original source checkpoint or a real converted/quantized checkpoint.
- Use Rosetta outputs for inspection, cross-model structural comparison, provenance routing, and candidate-hypothesis generation.
- Do not treat Rosetta descriptor corpora as trainable models, model merges, compressed brains, or recoverable weight encodings.
