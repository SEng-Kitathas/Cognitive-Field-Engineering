## Correct model-domain translation
The original Rosetta idea was not merely "put weights in a database." It was an attempt to translate LBE's software semantics into the model domain:

### Forge LBE
`source code -> evidence-bearing semantic field -> qualified composites -> interactive traversal/query -> counterfactual transformation -> verified source round-trip`

### Intended model LBE
`trained model -> evidence-bearing functional/structural field -> qualified model composites/operators -> selective StarMap/SoAoA traversal -> composed reasoning state -> optional verified adaptation/materialization`

The intended consumer-hardware win came from making the bulk substrate static and activating/traversing only a small relevant working set.

## Model-domain analogue of LBE puzzle piece
A viable model semantic composite would need more than tensor statistics. Its boundary would look approximately like:

`required state/context/capabilities`
`-> callable/activatable learned transformation`
`-> internal operator/activation subgraph`
`-> outputs/effects/state delta`
`-> provided capabilities`

plus:
- functional evidence;
- model/layer/tensor lineage;
- activation conditions;
- confidence/currentness;
- resource cost;
- compatibility constraints;
- known interactions;
- uncertainty/unknowns.

This is much closer to LBE's semantic-composite idea than a row of tensor mean/std metadata.

## Rosetta's actual position
Current Rosetta provides a useful **structural descriptor field** but not a functional LBE for models.

It gives:
`source model -> normalized tensor names/roles/shapes/quantization/sampled statistics/family relations`

It lacks:
`query-state semantics -> qualified functional composites -> routing -> composition -> updated reasoning state`.

Therefore:
`ROSETTA = MODEL ARCHAEOLOGY / STRUCTURAL CARTOGRAPHY INPUT`
not
`ROSETTA = COMPLETE MODEL LBE`.

## StarMap + SoAoA role
Historical StarMap/SoAoA remains a plausible implementation substrate for a model-domain LBE:
- immutable bulk storage;
- locality-preserving physical layout;
- typed adjacency / shape-of-reachability;
- selective traversal;
- small mutable state/router layer.

But LBE adds the semantic discipline Rosetta lacked: evidence-bearing boundaries, capabilities, requirements, effects, authority/qualification, currentness, and round-trip verification.

## Critical boundary carried across domains
Forge law:
`FIELD != MAP != VIEW != SOURCE MUTATION`.

Model translation:
`MODEL FUNCTION != DESCRIPTOR FIELD != STARMAP PROJECTION != WEIGHT MUTATION`.

A traversal hypothesis or visual/model map does not silently become a changed model. Any material adaptation still requires explicit compilation/materialization and evaluation against source/target behavior.

## Strongest research question if reopened
Can a powerful source model be compiled into **functionally qualified static composites** such that a much smaller active controller can select and compose only the required pieces while retaining useful reasoning capability at materially lower active-memory/compute cost than conventional inference?

That is the LBE-for-models question.
