## Purpose
Reconstruct historical StarMap mechanisms from the recovered E-drive corpus, strip them for parts, and map each part against current CFE without granting historical material authority merely because it resembles current ideas.

The source audit was partial rather than exhaustive: 238 confirmed content-hit files, 215 substantive files after obvious dependency/game filtering, 175 unique substantive contents, and ~4,402 `starmap` occurrences. The full ~2 TB E-drive traversal did not finish and was explicitly stopped.

## Executive finding
StarMap was not one architecture. At least four different mechanisms accumulated under the name:

1. **Cognitive/relevance geometry** — query concepts as nodes with salience, novelty, embeddings, weighted edges, tension, clusters, and traversal.
2. **Model-specific topology/index** — a rebuildable StarMap over a deeper canonical CIL/Universe, with multiple model-specific maps permitted simultaneously.
3. **Locality/physical topology** — Hilbert placement and later HOT/COLD graph topology for keeping near relations cheap while retaining long-range shortcuts.
4. **Generative pattern substrate** — Pattern StarMap/Forge idea in which the knowledge genome generates detection, enforcement, remediation, and explanation instead of remaining a passive catalog.

The strongest CFE salvage is not the old embedding math or literal Hilbert curve. It is the architectural separation and coupling principles beneath them.

# Salvage classification

## PROMOTE TO CFE RESEARCH PROGRAM
These are strong enough to become explicit CFE research hypotheses/design constraints, but not scientific laws until prospectively tested.

### S1 — FIELD != MAP
**Historical source:** NEAL v22.8 states that StarMap is the *index that observes the CIL (Universe)*, and is model-specific, ephemeral, rebuildable; multiple StarMaps can coexist.

**CFE translation:**
- Canonical source developmental field is not the learner-specific map of that field.
- Different learners/compilers may require different projections of the same source relations.
- A learner-specific projection may be invalidated/rebuilt without rewriting source history.

**Candidate law:**
`SOURCE FIELD != LEARNER-SPECIFIC FIELD PROJECTION`

**Why this matters:** It sharpens existing CFE distinctions among source geometry, compiled exposure geometry, optimizer-visible geometry, and learned geometry.

### S2 — GENERATIVE FIELD SPECIFICATION
**Historical source:** Pattern StarMap/Forge explicitly argues that the genome and enforcer must be the same knowledge at two abstraction levels: adding a pattern should automatically extend detection, remediation, and explanation.

**CFE translation:**
A CFE field specification should not be a descriptive sidecar beside hand-written schedules/evals. The same typed relation specification should generate:
- learner-visible exposure candidates,
- schedule constraints,
- controls,
- negative/anti-isomorph examples,
- evaluator coverage obligations,
- lineage/readback.

**Candidate law:**
`FIELD SPECIFICATION != PASSIVE SIDECAR`

A stronger engineering target is:
`FIELD SPECIFICATION -> COMPILER -> EXPOSURE + CONTROLS + EVALS + TRACE`

This directly attacks the existing scar `SIDECAR_GEOMETRY != GRADIENT_GEOMETRY`.

### S3 — TYPED EDGES, NOT GENERIC SIMILARITY
**Historical source:** Early StarMap stored nodes plus edge weight, angle, tension, type; later Forge work required directional trust chains and derivation graphs rather than boolean flags.

**CFE translation:**
The field needs typed relations that can distinguish at minimum:
- semantic similarity,
- contrast,
- attribution/provenance,
- temporal succession,
- causal/consequence relation,
- contradiction,
- prerequisite/dependency,
- recurrence,
- revision/staleness,
- intervention/counterfactual relation.

**Candidate law:**
`RELATIONAL DISTANCE != RELATIONAL TYPE`

Two nodes may be equally “near” while exerting radically different developmental pressure because the edge means something different.

### S4 — LOCAL + LONG-RANGE RELATIONAL TOPOLOGY
**Historical source:** NEAL StarMapGraph separated HOT local neighbors from COLD long-range shortcuts. KarnOS/Hilbert work separately tried to preserve locality in physical mapping.

**CFE translation:**
Do not import cache semantics literally. Preserve the deeper topology hypothesis:
- dense local recurrence can build a neighborhood,
- sparse long-range returns can connect distant developmental episodes,
- both may be necessary,
- local and long-range relations should be manipulated independently.

**Candidate law:**
`LOCAL COHERENCE != LONG-HORIZON CONNECTIVITY`

This is a direct bridge from current Identifying CFE toward true long-horizon developmental experiments.

### S5 — DYNAMIC ACTIVATION / TEMPORAL RELEVANCE
**Historical source:** StarMap nodes carried salience, novelty, order; later NEAL topology carried node activation and version invalidation. Novelty was explicitly calculated relative to prior CIL history.

**CFE translation:**
A developmental field should eventually support stateful relevance rather than static adjacency:
- recency and decay,
- repeated activation,
- unresolved uncertainty,
- stale associations,
- consequence-triggered reactivation,
- revision after contradictory evidence.

**Candidate principle:**
`STATIC GRAPH != DEVELOPMENTAL FIELD`

### S6 — DERIVATION CHAINS / FIXED-POINT CONSEQUENCE
**Historical source:** Forge noted that single-pass enforcement cannot support two-hop/three-hop derivation and proposed bounded fixed-point iteration with provenance.

**CFE translation:**
For Developmental CFE, consequences should be able to propagate across time and intermediate state. A learner must sometimes experience A, then B, then later discover that C changes the interpretation or consequence of A.

**Candidate principle:**
`ONE-HOP CO-OCCURRENCE != CAUSAL DEPTH`

This is especially relevant to CFE’s existing law `LONG CONTEXT != LONG-HORIZON COGNITION`.

## ADAPT — useful mechanism, wrong historical embodiment

### A1 — Salience
Old implementation used query position/frequency. Keep the concept, discard the heuristic. CFE salience should arise from developmental consequence, recurrence, uncertainty, task relevance, or experimentally controlled exposure pressure—not textual position alone.

### A2 — Novelty relative to history
Keep the historical-relative definition, discard the specific cosine-centroid formula as universal. Novelty may be semantic, causal, policy-relevant, structural, or consequence-based.

### A3 — Edge tension
Keep “relation carries stress/conflict” as a field dimension. Discard `abs(salience_a - salience_b)` as an adequate definition. CFE tension should be grounded in incompatible predictions, outcomes, causal models, or unresolved evidence.

### A4 — Clusters / constellations
Keep as a compiler primitive for local field organization. Do not assume clusters are learner ontology or that embedding clusters equal cognitive structure.

### A5 — Multiple maps over one universe
Strong architecture pattern. In CFE this could mean separate projections for learner, evaluator, curator, or different learner classes. They must remain explicitly non-equivalent.

## QUARANTINE — interesting, but not currently justified as CFE mechanism

### Q1 — Literal Euclidean/radial vector geometry
The old `phi(D) -> R^k`, cosine/L2 distance, angle and centroids are useful implementation tools but cannot be treated as the field itself. Current CFE experiments already show curator-visible geometric neatness does not imply learned geometry.

### Q2 — Hilbert curve as cognitive law
Hilbert locality is a legitimate physical/data-layout technique. There is no evidence that a Hilbert curve is a privileged developmental geometry for cognition. Preserve only the abstraction: locality-preserving compilation may matter.

### Q3 — HOT/COLD = cache semantics
The hardware optimization is real in its original context, but CFE should translate it into local-vs-long-range relational access, not import L1/prefetch language as cognitive doctrine.

### Q4 — “Council of Sages” multi-model StarMaps
Useful evidence that the historical architecture recognized map-dependence on the observer/model. Multi-model councils themselves are not required by CFE and should not be ported automatically.

## DISCARD FROM CFE CORE

### D1 — Query-position salience formula
`0.6 * position + 0.4 * frequency` is an implementation convenience, not a developmental law.

### D2 — Similarity threshold > 0.3 as generic edge creation
This collapses relation existence into embedding proximity and erases causal/temporal/attribution types.

### D3 — Tension = salience difference
Too weak and semantically ungrounded for CFE.

### D4 — “Star-like/radial layout” as literal requirement
The visual metaphor is not the mechanism. CFE cares about relational topology and developmental exposure, not a radial drawing.

### D5 — Any historical claim that StarMap itself was already a cognitive substrate
Historical documents/specs are design evidence, not empirical CFE evidence. No retroactive promotion.

# Reconstructed lineage

## Stage 1 — StarMap as cognitive geometry
Confirmed in AI 4.0/4.1 and NEAL context material. Nodes represented concepts; fields included vector, salience, novelty, order, tags. Edges held weight, angle, tension, and type. Clusters held centroid/coherence. Query-to-map construction built embeddings, salience, novelty, edges, and clusters.

**Value now:** vocabulary for explicit field topology.
**Failure now:** mostly semantic-similarity geometry; curator ontology too strong.

## Stage 2 — StarMap as model-specific index over canonical history
NEAL later makes the crucial distinction: StarMap is not the Universe/CIL; it is a model-specific ephemeral index over it, rebuildable and versioned.

**Value now:** very strong CFE architectural pattern for source field versus learner/compiler projection.

## Stage 3 — StarMap as topology-aware locality
NEAL v22.x unifies graph navigation and physical topology using local HOT neighbors plus long-range COLD shortcuts. KarnOS separately applies Hilbert locality to memory placement/isolation.

**Value now:** abstract local-vs-long-range connectivity and locality-preserving compilation.
**Failure now:** physical/cache details are not evidence about cognition.

## Stage 4 — Pattern StarMap as generative knowledge
Forge reframes StarMap from a catalog into a source whose invariants/anti-patterns/axioms generate runtime gates, transformations, explanations, and derivation chains.

**Value now:** strongest engineering salvage. A CFE field schema should generate its executable developmental intervention and its evaluator obligations from one source of truth.

# CFE architecture delta proposed from salvage

Current CFE should evolve toward four explicitly separated layers:

1. **Canonical Developmental Field (CDF)**
   - immutable/revisioned events and typed relations
   - curator-level causal, temporal, attribution, contrast, consequence, contradiction edges
   - no assumption that these labels are learner-visible

2. **Learner Field Projection (LFP)**
   - model/compiler-specific projection of CDF
   - chooses which relations become visible through adjacency, recurrence, ordering, delay, omission, contrast, or consequence
   - ephemeral/rebuildable like historical StarMap index

3. **Exposure Compiler (EC)**
   - compiles LFP into actual sequences/windows/interactions
   - must expose compiled geometry rather than hide it in sidecars
   - emits controls and identity hashes

4. **Field Verifier (FV)**
   - generates coverage tests/evaluations from the same typed field spec
   - checks source geometry, learner-visible projection, optimizer-visible geometry, and earned phenotype separately

Core architecture law candidate:

`CANONICAL FIELD != LEARNER PROJECTION != EXPOSURE COMPILATION != LEARNED GEOMETRY`

# Prospectively testable branches created by this salvage

## Branch ST-1 — Typed-edge identifiability
Hold node/event content fixed. Compare fields with the same adjacency count but different relation types made learner-visible through controlled sequences: similarity-only vs contrast vs causal consequence vs temporal recurrence.

Question: does relation *type* produce separable phenotypes beyond generic proximity?

## Branch ST-2 — Local/long-range topology
Hold examples fixed. Compare:
- local-only recurrence,
- long-range-only recurrence,
- local + sparse long-range shortcuts.

Question: can sparse re-encounter across developmental distance produce transfer unavailable to dense local neighborhoods?

## Branch ST-3 — History-relative activation
Teach an association, let it become stale or contradicted, then reintroduce causal evidence later.

Question: can the field induce revision/uncertainty behavior rather than static recall?

## Branch ST-4 — Generative field compiler validation
Define a small typed canonical field and automatically generate exposure schedules + matched controls + evaluator coverage from it.

Question: does one-source field generation reduce source/compiler/eval drift and make geometry interventions reproducible?

This is primarily an engineering-identity experiment, not a cognition claim.
